# Modeling and evidence

Graphs suit this problem because the useful questions follow heterogeneous paths: actor -> technique, malware -> domain -> IP -> report, or CVE -> weakness/product. Neo4j expresses bounded neighborhoods and relationships directly; a relational schema can model the same facts but repeated joins become cumbersome as path length/types change. Relational storage remains useful for ingestion manifests, tabular evaluations and audit records; a graph is not intrinsically more accurate.

Every node has global Entity.id plus one allowlisted type. STIX IDs identify ATT&CK objects; external_id stores ATT&CK T/G/S identifiers and is indexed but not globally unique across domains/releases. CVE/CWE IDs are standardized identifiers; products use the source's CPE string or KEV vendor/product key. Those product keys are **not silently merged**: fuzzy product reconciliation remains a human data-curation choice. IOCs use normalized type:value IDs. Campaign is retained rather than squeezed into actor properties. Technique sub-techniques are individual nodes because they have separate IDs and evidence.

All 13 node kinds and 11 relationships requested by the specification are supported. Static identifier uniqueness constraints cover every node and relationship ID. Property indexes cover each type's external_id plus Entity.name and source support. Relationships use a deterministic (source, type, target) key. Multiple publishers support one relationship through separate observations instead of duplicate edges.

ATT&CK mapping: intrusion-set/threat-actor -> ThreatActor; malware -> Malware; tool -> Tool; campaign -> Campaign; attack-pattern -> Technique. uses -> USES; attributed-to -> ATTRIBUTED_TO with hypothesis/caveat; targets -> TARGETS; related-to -> SIMILAR_TO with original semantics retained. subtechnique-of uses a Technique-to-Technique USES edge **only as a taxonomy encoding** with original_relationship=subtechnique-of; actor profiles explicitly filter ThreatActor -> Technique, so taxonomy edges do not become actor actions. Revoked/deprecated objects and edges are excluded. Unknown relationship types are not guessed. STIX identities, markings and collection metadata are not graph nodes in this scoped schema; original bundles remain in ignored cache.

Relationships are explicit assertions. COMMUNICATES_WITH/RESOLVES_TO in the synthetic sample are authored offline assertions, never observed by live requests. MENTIONED_IN means text occurrence, not attribution or exploitation. ATT&CK CVE co-mentions are not transformed into EXPLOITS edges; a source must explicitly support any such assertion.

Evidence fields: source, source_id, first_seen, last_seen, confidence (0..1), ingestion_run_id. ATT&CK dates are STIX object creation/modification dates, not first/last attacker activity. KEV dateAdded is catalog observation date. Local report dates are publisher supplied. Confidence describes source/assertion support and is **not a calibrated attribution probability**; deterministic imported facts default to 1.0 source-fidelity, not certainty of the underlying real-world hypothesis.

The in-memory and Neo4j models retain per-property observations. The materialized property view uses latest last_seen timestamp then deterministic source/ID ordering; conflicting observations are retained rather than erased. Neo4j evidence records serialize both provenance and the contributing properties; native provenance arrays are recomputed on each merge. Repeated identical loads are idempotent. New source/run support is additive. Purge recomputes properties from surviving observations and removes unsupported nodes/edges; endpoints also receive relationship evidence so a shared edge is not accidentally deleted with its first source. Purge is maintenance and requires ingestion to be paused.

Aliases remain reversible ALIAS_OF hypotheses. Exact ATT&CK overlaps suggest candidates; ambiguous names go to review. Embedding candidates >=0.92 are eligible for review/approval, 0.75..0.92 require review, and lower candidates are rejected. Even eligible links are not destructive auto-merges. This conservative choice reflects the higher cost of false merges.

Analytics export explicitly selected IDs, capped at 5,000 nodes/30,000 edges. API refuses larger snapshots and supports CTIG_SUBGRAPH pointing to an ignored JSON ID list. NetworkX uses an undirected simple observed projection: parallel relation types collapse, inferred edges are excluded. Degree, PageRank and betweenness describe that projection. Pivot depth <=3, render <=200, hub filter default 50. Those operations never run on an uncapped full database graph.
